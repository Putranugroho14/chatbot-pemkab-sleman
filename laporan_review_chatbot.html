📌 Kriteria Evaluasi Utama:
Setiap platform dievaluasi berdasarkan 5 kriteria wajib berikut:
1. Self-hosted — Dapat diinstal dan dijalankan di server sendiri (on-premise / lokal) tanpa ketergantungan cloud pihak ketiga.
2. Agentic Workflow — Mendukung pembuatan AI Agent yang dapat merencanakan, menggunakan tools, dan menjalankan alur kerja multi-langkah secara otomatis.
3. Multi-Agent & Knowledge Isolation — Dapat membuat banyak agen terpisah di mana setiap agen hanya memiliki akses ke knowledge base-nya sendiri (data silo).
4. Embeddable — Menyediakan mekanisme untuk menyematkan widget chat ke website atau platform lain (iframe, script, API).
5. Production Ready — Stabil, memiliki manajemen pengguna, dan dapat digunakan dalam lingkungan produksi pemerintahan.

REVIEW PLATFORM #1 — FLOWISE
Judul : Flowise – Drag & Drop UI to Build Your Customized LLM Flow (Agentic Pipeline Builder)
Jurnal/Platform : FlowiseAI – docs.flowiseai.com | GitHub: FlowiseAI/Flowise
Versi & Rilis : v2.x (2024) – Open Source, MIT License
Tahun : 2023–2024
Pengembang : Henry Heng & Komunitas Open Source FlowiseAI
Reviewer : ___________________________
Tanggal Review : 25 Juli 2026
HASIL REVIEW
Rumusan Masalah : Apakah Flowise mampu memenuhi kebutuhan platform self-hosted agentic workflow dengan kemampuan multi-agent yang terisolasi per knowledge base dan dapat di-embed ke website instansi pemerintahan?
Tujuan / Ide Pokok : Flowise menyediakan antarmuka visual berbentuk canvas drag-and-drop untuk membangun pipeline LLM dan AI Agent secara no-code. Platform ini menargetkan developer yang ingin membangun aplikasi AI kompleks tanpa menulis kode dari awal, menjadikannya kandidat awal yang menjanjikan sebagai platform agentic.
Metode / Teknologi : Node.js backend + React frontend. Mendukung LangChain Agent nodes (ReAct, OpenAI Function Agent), Tool nodes (Calculator, Web Search, Custom API), dan Memory nodes. Setiap Chatflow dapat diekspos sebagai embed widget via script tag atau iframe. Self-host via Docker dengan satu container ringan.
Evaluasi Kriteria Utama : ✅ Self-hosted: Ya — Docker single container, sangat ringan (~512MB RAM).
✅ Agentic Workflow: Ya — Mendukung ReAct Agent, Tool Calling Agent, Multi-step reasoning via node graph.
⚠️ Multi-Agent & Knowledge Isolation: Parsial — Setiap Chatflow terpisah dan memiliki Vector Store sendiri, namun tidak ada sistem manajemen pengguna/tenant yang mencegah akses antar Chatflow secara native. Isolasi bergantung pada URL API key yang berbeda.
✅ Embeddable: Ya — Tersedia embed script, iframe, dan React/Vue/Angular component. Sangat mudah disematkan ke website mana pun.
⚠️ Production Ready: Parsial — Cocok untuk prototype dan deployment kecil, namun manajemen pengguna multi-tenant belum enterprise-grade.
Hasil Pengujian : Flowise berhasil digunakan membangun prototipe chatbot RAG dengan Ollama (Llama 3.2) secara lokal. Pembuatan Agent dengan tool "retrieval dari knowledge base" selesai dalam <1 jam. Fitur embed berhasil menampilkan widget chat di halaman HTML statis. Namun, saat dicoba membuat 2 agent terpisah (Kominfo & Pariwisata), tidak ada mekanisme bawaan yang mencegah pengguna mengakses Chatflow lain jika memiliki API key-nya.
Kekuatan Platform : 1. Termudah digunakan — kurva belajar paling rendah dari semua platform.
2. Embed paling fleksibel — 1 baris script sudah cukup memasang chat widget.
3. Komunitas besar & dokumentasi lengkap.
4. Self-host ringan, cocok untuk server dengan resource terbatas.
Kelemahan Platform : 1. Knowledge Isolation lemah — Tidak ada hard isolation antar agent/tenant secara native; berbahaya untuk data sensitif pemerintahan.
2. Tidak ada sistem RBAC yang memadai untuk pengelolaan multi-departemen.
3. Parsing dokumen pemerintahan kompleks (PDF bертable) masih terbatas.
Kesimpulan : Flowise adalah pilihan terbaik untuk prototyping cepat dan embedding. Namun, karena isolasi knowledge base antar agent tidak bersifat hard isolation, platform ini tidak memenuhi standar keamanan data untuk deployment multi-dinas di lingkungan pemerintahan. Tidak dipilih sebagai solusi final.
Referensi : FlowiseAI. (2024). Flowise Documentation. https://docs.flowiseai.com | https://github.com/FlowiseAI/Flowise

REVIEW PLATFORM #2 — DIFY
Judul : Dify – Open Source LLM Application Development Platform with Agentic Workflow & Multi-Tenant Knowledge Base
Jurnal/Platform : Dify.AI – docs.dify.ai | GitHub: langgenius/dify
Versi & Rilis : v0.6.x – v0.9.x (2024), Docker Compose Self-Hosted
Tahun : 2023–2024
Pengembang : LangGenius Inc. (Luyu Zhang & Tim)
Reviewer : ___________________________
Tanggal Review : 25 Juli 2026
HASIL REVIEW
Rumusan Masalah : Apakah Dify mampu memenuhi kebutuhan platform self-hosted agentic workflow dengan multi-agent knowledge isolation yang ketat dan kemampuan embed ke website pemerintahan?
Tujuan / Ide Pokok : Dify hadir sebagai platform LLM end-to-end yang mencakup pembuatan chatbot, RAG pipeline, AI Agent, dan Workflow Orchestration visual dalam satu platform terintegrasi. Dify dirancang untuk production-ready dengan sistem workspace dan manajemen pengguna bawaan.
Metode / Teknologi : Docker Compose stack: Flask API + Celery Worker + Next.js Frontend + PostgreSQL + Redis + Weaviate/pgvector. Agent berbasis Function Calling & ReAct. Workflow editor visual untuk multi-step pipeline. Knowledge Base dengan hybrid search (keyword + semantic). Embed via script tag, iframe, atau API endpoint.
Evaluasi Kriteria Utama : ✅ Self-hosted: Ya — Docker Compose, fully on-premise, mendukung Ollama lokal.
✅ Agentic Workflow: Ya — Workflow editor visual sangat powerful; mendukung Agent node, If/Else branching, Iteration, Code execution, Tool integration.
❌ Multi-Agent & Knowledge Isolation: Tidak — Meskipun Dify memiliki fitur multiple App dan Workspace, pada pengujian nyata isolasi antar agent tidak berjalan sebagaimana diharapkan. Seorang pengguna dapat dijadikan member di beberapa Workspace sekaligus dan mengakses semua App di dalamnya; tidak ada mekanisme teknis yang mencegah hal ini secara paksa (hard isolation).
✅ Embeddable: Ya — Tersedia embed script, bubble button, dan fullscreen iframe. Dapat dikustomisasi warna dan logo.
✅ Production Ready: Ya — Memiliki SSO, API key management, log percakapan, annotation, dan monitoring.
Hasil Pengujian : Dify berhasil di-deploy dengan Docker. Knowledge Base dibuat dari file TXT Kominfo dan Pariwisata. Dua App chatbot terpisah dibuat dengan Knowledge Base berbeda — saat chatbot Kominfo ditanya tentang Pariwisata, ia tidak menemukan jawaban (isolasi berhasil secara fungsional). Embed widget berhasil muncul di halaman web. Namun konsumsi RAM mencapai 6–8 GB yang menyebabkan konflik dengan layanan Docker lain.
Kekuatan Platform : 1. Workflow visual terlengkap — Editor node-based dengan fitur conditional, iteration, dan code block.
2. Knowledge isolation fungsional — Setiap App terisolasi ke Knowledge Base-nya sendiri.
3. Embed paling kaya fitur — mendukung kustomisasi tampilan widget.
4. Monitoring & analytics percakapan bawaan.
5. Komunitas paling aktif & update paling cepat.
Kelemahan Platform : 1. Resource sangat besar — RAM 6–8 GB untuk Dify saja, belum Ollama (~4 GB). Total >10 GB RAM dibutuhkan.
2. Isolasi antar workspace tidak sekeras RAGFlow (shared database infrastructure).
3. Port default 80/443 sering konflik dengan layanan lain.
4. Kompleksitas setup Docker Compose dengan 8+ container.
Kesimpulan : Dify adalah platform yang paling memenuhi semua kriteria utama secara fungsional — self-host, agentic workflow, multi-agent dengan knowledge isolation, dan embeddable. Namun kebutuhan resource yang sangat besar menjadi kendala untuk server pemerintahan dengan resource terbatas. Dify menjadi kandidat kuat namun tidak dipilih karena kendala resource.
Referensi : LangGenius. (2024). Dify Documentation. https://docs.dify.ai | https://github.com/langgenius/dify

REVIEW PLATFORM #3 — OPEN WEBUI
Judul : Open WebUI – Extensible, Self-Hosted AI Interface with Multi-User Knowledge Base Management
Jurnal/Platform : Open WebUI – docs.openwebui.com | GitHub: open-webui/open-webui
Versi & Rilis : v0.3.x – v0.5.x (2024), Docker Image: ghcr.io/open-webui/open-webui
Tahun : 2023–2024
Pengembang : Tim Baek & Komunitas Open Source
Reviewer : ___________________________
Tanggal Review : 25 Juli 2026
HASIL REVIEW
Rumusan Masalah : Apakah Open WebUI mampu memenuhi kebutuhan platform self-hosted dengan kemampuan multi-agent knowledge isolation per departemen, agentic workflow, dan fitur embed ke website pemerintahan?
Tujuan / Ide Pokok : Open WebUI bertujuan menyediakan antarmuka web lengkap menyerupai ChatGPT untuk model AI yang berjalan lokal via Ollama. Fokus utamanya adalah user experience, manajemen multi-user, dan Knowledge Base per grup/user. Dirancang sebagai "ChatGPT for your own server."
Metode / Teknologi : SvelteKit frontend + Python/FastAPI backend. Vector store: ChromaDB internal. Sistem RBAC: Admin, User, Groups. Knowledge Base dapat dibuat per grup dan dikontrol aksesnya. Tools/Functions dapat ditambahkan via plugin Python. Komunikasi ke Ollama via REST API lokal.
Evaluasi Kriteria Utama : ✅ Self-hosted: Ya — Docker single container sangat ringan (~500MB RAM). Setup paling mudah.
⚠️ Agentic Workflow: Terbatas — Mendukung Tools (Function Calling) namun tidak ada workflow editor visual seperti Dify. Agent bersifat conversational, bukan pipeline multi-step.
⚠️ Multi-Agent & Knowledge Isolation: Parsial — Knowledge Base dapat diisolasi per grup, namun isolasi tidak bersifat hard isolation; model LLM yang sama digunakan semua user dan berpotensi bocor lintas konteks dalam skenario tertentu.
❌ Embeddable: Tidak — Open WebUI tidak menyediakan fitur embed widget / chat iframe untuk disematkan ke website eksternal.
✅ Production Ready: Ya — Manajemen user, Groups, RBAC, dan log percakapan tersedia.
Hasil Pengujian : Open WebUI berhasil dikonfigurasi sebagai platform multi-departemen. Knowledge Base per dinas berhasil dibuat dan diisolasi via Groups. Namun, tidak ditemukan fitur untuk mengekspos widget chat ke halaman website eksternal — platform ini hanya dapat diakses melalui URL internal-nya sendiri. Ini menjadi hambatan kritis untuk kebutuhan embed di website publik dinas.
Kekuatan Platform : 1. Paling ringan — hanya ~500MB RAM, ideal untuk server resource terbatas.
2. UX terbaik — antarmuka paling intuitif dan ramah pengguna non-teknis.
3. Update paling cepat — komunitas sangat aktif (50k+ GitHub stars).
4. Manajemen user & RBAC bawaan yang solid.
Kelemahan Platform : 1. Tidak ada fitur Embed — Tidak dapat disematkan sebagai widget di website lain; ini merupakan kegagalan kritis terhadap kriteria utama.
2. Agentic workflow sangat terbatas — hanya tool calling, tidak ada pipeline visual.
3. Knowledge isolation tidak sempurna (soft isolation).
4. Tidak cocok untuk menjadi public-facing chatbot di website instansi.
Kesimpulan : Open WebUI sangat baik sebagai platform chat internal untuk staf pemerintahan, namun gagal memenuhi kriteria embeddable yang merupakan kebutuhan utama untuk menyematkan chatbot ke website publik dinas. Platform ini lebih cocok sebagai "internal AI assistant" bukan "public chatbot." Tidak dipilih sebagai solusi final.
Referensi : Baek, T. (2024). Open WebUI Documentation. https://docs.openwebui.com | https://github.com/open-webui/open-webui

REVIEW PLATFORM #4 — RAGFLOW
Judul : RAGFlow – Deep Document Understanding-Based Open Source RAG Engine for Enterprise Multi-Tenant Knowledge Management
Jurnal/Platform : InfiniFlow RAGFlow – ragflow.io/docs | GitHub: infiniflow/ragflow
Versi & Rilis : v0.9.x – v0.12.x (2024), Docker Compose Enterprise Stack
Tahun : 2024
Pengembang : InfiniFlow Team
Reviewer : ___________________________
Tanggal Review : 25 Juli 2026
HASIL REVIEW
Rumusan Masalah : Apakah RAGFlow mampu memenuhi kebutuhan platform self-hosted dengan isolasi knowledge base antar agent yang ketat (hard isolation), kemampuan agentic workflow, dan fitur embed widget ke website dinas?
Tujuan / Ide Pokok : RAGFlow bertujuan menjadi RAG engine kelas enterprise dengan kemampuan Deep Document Understanding (DDU) — mampu mengekstraksi tabel, bagan, dan struktur kompleks dari PDF secara akurat. Dirancang khusus untuk enterprise dengan multi-tenant hard isolation via RBAC native.
Metode / Teknologi : Docker Compose stack: Python API + React Frontend + MySQL + MinIO + Redis + Infinity/Elasticsearch (vector DB). DDU engine menggunakan PaddleOCR dan layout detection AI. Agent berbasis "Chat Apps" yang terikat ke Dataset spesifik. Embed via API endpoint & iframe widget bawaan.
Evaluasi Kriteria Utama : ✅ Self-hosted: Ya — Fully on-premise, 100% offline (air-gapped), mendukung Ollama lokal.
⚠️ Agentic Workflow: Parsial — Mendukung Agent mode dengan tool calling (web search, API call, code), namun tidak ada workflow editor visual seperti Dify. Pipeline agentic bersifat linear, bukan graph-based.
✅ Multi-Agent & Knowledge Isolation: Ya — TERBAIK dari semua platform. Setiap "Chat App" terikat ke Dataset tertentu secara hard. RBAC native memastikan staf Dinas A tidak bisa melihat Dataset Dinas B secara teknis.
✅ Embeddable: Ya — Setiap Chat App memiliki embed URL dan iframe code yang dapat langsung disematkan ke website.
✅ Production Ready: Ya — Enterprise-grade dengan user management, audit log, similarity threshold konfigurasil, dan anti-hallucination "Empty Response."
Hasil Pengujian : RAGFlow berhasil di-deploy (port diubah ke 8080 untuk menghindari konflik). Model Ollama (Llama 3.2) dan embedding (nomic-embed-text) terintegrasi. Dataset Kominfo & Pariwisata dibuat terpisah. Akun staf Pariwisata yang login tidak dapat melihat Dataset Kominfo — isolasi terbukti keras (hard isolation). Embed URL Chat App berhasil ditampilkan di halaman web. Akurasi RAG 100% pada pertanyaan berbasis dokumen TXT.
Kekuatan Platform : 1. Knowledge isolation terkuat — Hard isolation via RBAC; data completly terisolasi per tenant.
2. Deep Document Understanding — Parsing dokumen PDF kompleks (tabel, bagan) paling akurat.
3. Embed bawaan — Setiap Chat App langsung memiliki embed code.
4. Anti-hallucination configurable — "Empty Response" jika tidak ada dokumen relevan.
5. Fully offline — 100% air-gapped, aman untuk data pemerintahan.
Kelemahan Platform : 1. Resource sangat tinggi — RAM 10–12 GB untuk infrastructure RAGFlow saja.
2. Agentic workflow terbatas — Tidak ada workflow editor visual; agent bersifat linear.
3. Setup kompleks — 8+ Docker container dengan risiko race condition saat startup.
4. Waktu boot lama (5–10 menit hingga semua service healthy).
Kesimpulan : RAGFlow adalah platform terpilih sebagai solusi final untuk proyek Diskominfo Sleman. Keunggulannya pada hard isolation knowledge base antar agent, fitur embed bawaan, kualitas RAG tertinggi, dan operasi 100% offline menjadikannya satu-satunya platform yang memenuhi seluruh kriteria keamanan dan fungsional utama proyek ini, meskipun agentic workflow-nya masih lebih terbatas dibanding Dify.
Referensi : InfiniFlow. (2024). RAGFlow Documentation. https://ragflow.io/docs | https://github.com/infiniflow/ragflow

REVIEW PLATFORM #5 — NYAI & SUPPORT BOARD
Judul : Nyai & Support Board – AI-Powered Multi-Channel Customer Service Platform with Knowledge Base Integration
Jurnal/Platform : Support Board (board.support) & Nyai (nyai.tech) – Dokumentasi Resmi
Versi & Rilis : Support Board v3.x – v4.x (2024); Nyai sebagai AI Layer Cloud
Tahun : 2022–2024
Pengembang : Schiocco & Tim Support Board; Nyai sebagai AI integration provider
Reviewer : ___________________________
Tanggal Review : 25 Juli 2026
HASIL REVIEW
Rumusan Masalah : Apakah Nyai dan Support Board mampu memenuhi kebutuhan platform self-hosted dengan agentic workflow, multi-agent knowledge isolation, dan kemampuan embed ke website pemerintahan — terutama tanpa mengirim data ke server cloud pihak ketiga?
Tujuan / Ide Pokok : Support Board adalah platform live chat customer service yang dapat diintegrasikan dengan AI (melalui Nyai atau OpenAI) untuk mengotomatiskan balasan pertanyaan umum. Nyai menyediakan layer AI berbasis cloud dengan kemampuan knowledge base kustom. Keduanya difokuskan pada automasi customer service multi-channel (Web, WhatsApp, Telegram).
Metode / Teknologi : Support Board: PHP backend + MySQL + JavaScript widget (dapat self-host di server sendiri). Nyai: Cloud-based AI layer yang terhubung ke Support Board via API. Embed: Support Board menyediakan JavaScript widget yang sangat mudah disematkan ke website manapun. Multi-channel via integrasi WhatsApp Business API, Telegram Bot, Facebook Messenger.
Evaluasi Kriteria Utama : ⚠️ Self-hosted: Parsial — Support Board (PHP) dapat self-host, namun komponen AI (Nyai) berjalan di cloud eksternal. Data percakapan dan dokumen dikirim ke server Nyai.
❌ Agentic Workflow: Tidak — Tidak ada fitur agentic workflow atau multi-step reasoning. AI hanya bersifat Q&A sederhana berbasis knowledge base.
❌ Multi-Agent & Knowledge Isolation: Tidak — Tidak ada sistem multi-agent. Satu instalasi hanya mendukung satu knowledge base global tanpa isolasi antar departemen.
✅ Embeddable: Ya — Widget JavaScript very easy to embed; ini justru kekuatan utama platform ini.
⚠️ Production Ready: Parsial — Baik untuk customer service konvensional, namun ketergantungan cloud Nyai menciptakan risiko keamanan data untuk pemerintahan.
Hasil Pengujian : Widget Support Board berhasil disematkan ke halaman web simulasi dan chat berfungsi normal. AI via Nyai mampu menjawab pertanyaan umum. Namun, tidak ditemukan cara untuk mengisolasi knowledge base antara Dinas Kominfo dan Pariwisata dalam satu instalasi. Semua percakapan tersimpan di server Nyai (cloud), yang bertentangan dengan kebijakan data sovereignty pemerintahan.
Kekuatan Platform : 1. Embeddable terbaik — Widget chat paling mudah dan rapi disematkan ke website.
2. Multi-channel out-of-the-box — WhatsApp, Telegram, FB Messenger langsung tersedia.
3. Human escalation — Fitur handover dari AI ke agen manusia tersedia native.
4. Ticket management — Pengelolaan pengaduan masyarakat terintegrasi.
5. Setup paling sederhana — Cukup PHP hosting standar.
Kelemahan Platform : 1. AI tidak self-hosted — Komponen Nyai berjalan di cloud; data sensitif pemerintah terkirim ke server eksternal.
2. Tidak ada multi-agent isolation — Kegagalan kritis terhadap kriteria utama.
3. Tidak ada agentic workflow — AI hanya Q&A sederhana, tidak bisa multi-step reasoning.
4. Kontrol AI sangat terbatas — Tidak ada konfigurasi threshold, empty response, atau system prompt mendalam.
Kesimpulan : Nyai & Support Board unggul dalam hal embed dan multi-channel, namun gagal pada hampir semua kriteria teknis utama: AI tidak self-hosted, tidak ada multi-agent isolation, dan tidak ada agentic workflow. Platform ini lebih cocok untuk bisnis swasta yang memprioritaskan kemudahan setup dan multi-channel, bukan untuk instansi pemerintah dengan kebutuhan keamanan data ketat. Tidak dipilih sebagai solusi final.

Nyai. (2024). Nyai – AI for Businesses. https://nyai.tech
